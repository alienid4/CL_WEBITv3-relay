## 二、四種狀態（外加「一般有值」）

### 2.1 判定來源

**一個純函式 `numState()`**（草案，放 `composables/v2Fact.ts`，**後端欄位沿用現有名稱**）：

```ts
type V2NumState = 'value' | 'zero' | 'nodata' | 'error' | 'denied'

function numState(b: { n: number | null; status?: string }, httpStatus?: number): V2NumState {
  if (httpStatus === 401 || httpStatus === 403) return 'denied'          // 前端判：apiFetch 丟出 statusCode
  if (httpStatus && httpStatus >= 400 || httpStatus === 0) return 'error' // 前端判：5xx／逾時／網路
  if (b.status === 'error') return 'error'                                // 後端判：算不出來（現有 label「無法計算」）
  if (b.n == null) return 'nodata'                                        // 後端判：來源沒資料（disabled／uncollected／stale）
  return b.n === 0 ? 'zero' : 'value'
}
```

| 狀態 | 誰判 | 判定欄位 | 現有程式碼對應 |
|---|---|---|---|
| **確定為 0**（`zero`） | 後端給數字、前端比 0 | `n === 0` 且 `status` 為 `ok`（或沒給 status）且 `as_of` 有值 | `v2_today.py` 各 block `n: 0`；`index.vue:48` 的 `${b.n} 件` |
| **沒收集**（`nodata`） | 後端 | `n === null`，`status ∈ {disabled, uncollected, stale}`，原因在 `label` | `index.vue:48` 的對照表；`Coverage` 的 `unmanaged／pending／unsupported` 也歸這一類（「該有資料但沒有」） |
| **查詢失敗**（`error`） | 後端或前端 | 後端：`status === 'error'`；前端：`apiFetch` throw（非 401/403） | `index.vue:48`「無法計算」；各頁 `err.value = …載入失敗：…` |
| **沒權限**（`denied`） | 前端（後端本來就用 403 表示） | HTTP 401/403 | `Coverage.vue:14`、`night.vue:249`、`HostRelations.vue:40`；其餘靠 `useApi.ts:93` 的 toast |

兩個注意：
1. **`stale`（資料中斷）歸 `nodata`**：現有後端把它放在 `n:null` 底下（`v2_today.py` 心跳逾時，測試 `test_v2_today_track.py:87`）。但「資料過期」同時也是「有數字、但數字舊了」的情形（`Coverage` 的 `stale`），這種**不是第五種狀態**，而是任一有值狀態上的一個旗標 `staleness`（見 §四 證據列的「資料延遲」）。
2. **1.2 的 `noData` 必須從 `n_text` 搬回 `n`**：`changes.vue:60` 現在是 `n:0 ＋ n_text:'無資料'`，遷移時改成 `n:null`＋`status:'uncollected'`，否則「0 也能點」與「沒收集連到原因」會打架（見 §六 測試影響）。**這是口徑類改動，需後端 `/api/changes` 或前端 `catRows` 一處調整，需獨立審查。**

### 2.2 固定外觀

顏色一律用 `assets/css/main.css` 變數（淺色／深色都已定義，見 `main.css:35-42,86-91`）。**狀態色表示「狀態」，指標本身的好壞（例：異常件數大於 0 為壞）另用 `tone`，兩者不混。**

| 狀態 | 大字格（數字位置） | 小字（一行灰字） | 顏色變數 | 可點？ | 點了去哪 | 範例文字 |
|---|---|---|---|---|---|---|
| `value` | 數字＋單位 | 解讀（沿用各頁既有） | 數字 `--ink`（指標 tone 可用 `--warn`／`--bad`／`--good`） | 可 | **同一份計算的明細頁**，頂端有證據列（§四） | `12 台` |
| **`zero`** | `0`＋單位（不用「—」、不縮小） | 「已查過」＋資料時間 | 數字 `--ink`（好壞色看指標，例如異常 0 可用 `--good`）；**不得用灰色，灰色保留給 `nodata`** | **可** | 同一個明細頁，顯示**空表**＋證據列（查了哪個來源、什麼條件、資料時間、分母、被排除幾筆）。空表文字：「這個條件下沒有項目」＋證據列即「查過了」的證明 | `0 件`・`已查過 11:20` |
| **`nodata`** | 「—」（`--ink-aux`） | 原因短字（沿用 `countText`：未啟用／未收集／資料中斷）＋「看原因」 | 文字 `--warn-text`（沿用 `index.vue:454 .cnt.na`）；底色可用 `--warn-soft`（沿用 `index.vue:457 .na-line`） | 可 | 「為什麼沒資料」：來源名、最後一次收到時間（無則「從沒收到」）、判定原因、**去處理的按鈕**（例：去 4.1 啟用 WhatsUp、去 6.2 設備收集） | `—`・`未收集（今天還沒有快照）・看原因` |
| **`error`** | 「—」 | 「讀取失敗」＋「重試」按鈕 | 文字 `--bad`，底 `--bad-soft` | 「重試」可點；數字格本身點開看錯誤原文（`e.data.detail`） | 展開錯誤原因＋重試；**不得導去明細頁**（明細頁用同一支 API，會同樣失敗） | `—`・`讀取失敗・重試` |
| **`denied`** | 「—」＋鎖頭字樣（不用 emoji，用文字「無權限」） | 「需要管理員／檢視以上權限」之類後端 `detail` 原文 | 文字 `--ink-aux`（不是警告，是邊界） | **不可點**（沒有 `<a>`，避免點進去又 403） | 無；hover/聚焦顯示後端 `detail`（沿用 `useApi.ts` 的「您的帳號權限是…」） | `—`・`沒有權限查看` |

**排序**：`zero` 排 0、`value` 排實際值、`nodata／error／denied` 一律排最後（V2Table 的 `text(row)` 可讓顯示字與排序值分開，`Table.vue:2-3` 已支援）。
**匯出**：`zero` 匯出 `0`，`nodata／error／denied` 匯出空白＋原因欄（不可匯成 0）。
**無障礙**：每種狀態都有文字（不靠顏色），`denied` 用 `aria-disabled`。

### 2.3 為什麼 `zero` 一定要可點（回應 GPT #2）
- 「0」若不可點，使用者無法分辨「真的 0」與「查不到」；點進去看到「空表＋證據列」才是證據。
- 反向：`nodata` 點進去不是空表，而是「為什麼沒資料」，避免「點進去是空的所以以為是 0」。
- 驗收見 `03_代表頁選擇與驗收方式.md`。

## 三、共同資料結構：數值・範圍・來源・時間・錯誤・下鑽

V2Num（數字卡／行內數字）、V2Source（來源・時間）、V2Evidence（明細頂端證據列）**共用同一個物件 `V2Fact`**，不各自定義。

```ts
// composables/v2Fact.ts（草案）
export interface V2Scope {
  conditions: { key: string; label: string }[]      // 條件標籤：例「收集帳號連線成功」「最近 7 天」「排除退役」
  denominator: { n: number; label: string } | null   // 分母：例 { n: 4921, label: '現役主機' }；沒有分母概念的數字為 null
  excluded: { n: number; label: string; drill: V2Drill } | null   // 被排除 N 筆（可點）；null＝沒有排除
}
export interface V2Drill {
  to: string                       // 站內路由含 query，例 '/v2/changes?tab=daily&cat=collect_gap&date=2026-11-16'
  kind: 'list' | 'why' | 'retry' | 'none'   // list=明細清單；why=為什麼沒資料；retry=重新讀取；none=沒權限
  expect?: number                  // 點進去後明細應出現的筆數（＝value），用於一致性檢查
}
export interface V2FactError {
  kind: 'nodata' | 'failed' | 'denied'
  reason: string                   // 後端 label／detail 原文，不要自己翻
  code?: string                    // disabled／uncollected／stale／error 或 HTTP 狀態
}
export interface V2Fact {
  value: number | null             // 數值；zero=0；其餘非 value 狀態＝null（永遠不用 0 代替未知）
  unit: string                     // 件／台／筆
  scope: V2Scope                   // 範圍
  source: { key: string; label: string }   // 來源：例 { key:'whatsup', label:'WhatsUp Gold 告警' }
  asOf: string | null              // 時間：台北時間 'YYYY-MM-DD HH:MM[:SS]'，後端 as_of 原值
  delayMin: number | null          // 資料延遲（分鐘）；後端算（now - asOf），超過門檻才顯示
  error: V2FactError | null        // 錯誤；非 null 時 value 必為 null
  drill: V2Drill                   // 下鑽：永遠有（denied 時 kind='none'）
}
```

### 3.1 「加總＝下鑽同一份計算」怎麼在結構裡被保證

這條是專案硬規則（CLAUDE.md「加總與下鑽必須走同一份計算」）。結構裡用**三道**保證，缺一道就會被測試攔下：

1. **同源**：`V2Fact.value` 與明細清單 **來自同一個後端函式／同一個查詢條件**。現有範式照搬：服務盤點 `service_inventory.CARD_WHERE` 一份條件，`summary` 用它數、`list_services(card=)` 用它篩（`tests/asset_module/test_q82_card_drilldown.py`）；`v2_today.py` 各 block 同時回 `n` 與 `rows`。契約要求：**凡進 `V2Fact` 的數字，後端必須同時提供 `drill` 的查詢參數，且該參數餵給明細 API 後回的筆數 `total` 等於 `value`。**
2. **drill 帶 `expect`**：`V2Drill.expect === value`。明細頁（`V2Evidence` 的「共 N 筆」）若讀到路由 `?n=` 與實際 `total` 不同，**只顯示「資料已更新，重新整理」小字，不顯示警告紅字**（兩次查詢之間資料可能變了）；但自動測試用固定資料驗證兩者必須相等。
3. **一律走 `toFact()` 單一轉換器**：頁面不再自己拼 `${n} 件`、`r.n ? link : null`；改 `toFact(block, { drill })`。測試再加一條**靜態守門**：`pages/v2` 與 `components/v2` 內 `link:` 的條件式 null 分支（本次掃出的 99 處）只能減不能增（沿用 `test_v2_three_layers.py` 的「名單只能縮小」寫法）。

另外 `verify_numbers.py`（`deploy.sh [2d/7]`）對**正式機真實資料庫**的不變式（加總＝下鑽、子集≤母體）不變；契約**新增的每個 `V2Fact` 來源**都要在 `verify_numbers.py` 補一條對應不變式（CLAUDE.md 既有要求），第 0 批只寫出清單、不實作（見 03 號文件）。

### 3.2 對應現有後端欄位（不需改後端的部分）

| `V2Fact` 欄位 | 1.1 現有來源（`/api/v2/today` block） | 需新增？ |
|---|---|---|
